# Non-functional requirements

Quality requirements for the MagicVibe API. IDs are stable; reference them in commits and changes. Requirements that can
be checked as API behavior (privacy, integrity) are also written as requirements in the
related [specs](../../openspec/specs/).

| ID     | Area                        | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
|--------|-----------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| NFR-01 | Performance and scalability | The API is stateless and horizontally scalable. `GET /discovery/next` and `POST /reactions` target p95 < 200 ms with 100k users. No N+1 queries.                                                                                                                                                                                                                                                                                                                                                                    |
| NFR-02 | Async                       | All I/O is async: database (asyncpg) and S3.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| NFR-03 | Data integrity              | Every data rule is enforced both in the schema and by a database constraint, with the same constant. Two exceptions: the age rule depends on the current date and is checked in the schema only; rules that depend on other rows (at most `MAX_PROFILE_IMAGES` photos per profile, at most one current subscription per user, a match for every pair of mutual likes) are checked in the service after locking the parent rows (the profile, the user, or both users of a reaction). See [Data model](./models.md). |
| NFR-04 | Privacy                     | Telegram data and like messages are shown to other users only through match data. "Who liked me" shows public profile data only. Logs contain internal IDs only — no names, bios, usernames, messages or photos.                                                                                                                                                                                                                                                                                                    |
| NFR-05 | Localization                | The API returns English messages and stable error codes and does not localize. Region and city names are stored in Ukrainian as in KATOTTH. User text is stored as written (full Unicode).                                                                                                                                                                                                                                                                                                                          |
| NFR-06 | Logging                     | structlog, with a request ID on every request. The service token is never logged.                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| NFR-07 | Configuration               | All settings via environment variables (pydantic-settings) with a committed `.env.example`. No secrets in code.                                                                                                                                                                                                                                                                                                                                                                                                     |
| NFR-08 | Time                        | Timestamps are stored in UTC (`timestamptz`). Europe/Kyiv is used only for daily limit boundaries ([Plans](../plans.md)).                                                                                                                                                                                                                                                                                                                                                                                           |
